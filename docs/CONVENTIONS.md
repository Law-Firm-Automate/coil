## Hard rules
- `app/models.py` is the shared schema. Do NOT edit it. If you truly need a column, add it at the END of the class, keep it nullable/defaulted, and list it in your final report. `db.create_all()` will not migrate existing DBs, so delete `data/practice.db` and re-seed after any model change.
- Only touch files in your assignment. Do not edit base.html, helpers.py, services/*, app/__init__.py, or another module's blueprint/templates. If a shared helper is missing, put it in your own blueprint module.
- Money is integer cents everywhere. Use `parse_money()` for form input and the `|money` filter for output.
- Every POST form must include `{{ csrf() }}`. Public (unauthenticated) POST routes must live under one of these prefixes, which are CSRF-exempt: `/webhooks/`, `/intake/submit`, `/track/`, `/sign/`, `/pay/`, `/p/`, `/portal/`.
- Protect staff routes with `@login_required` (from `app.helpers`). Owner-only with `@owner_required`. Portal routes with `@portal_required`.
- Templates extend `base.html` (staff) or `public.html` (client-facing). Put templates in `app/templates/<module>/`. Use existing CSS classes in `app/static/app.css` (card, grid c2/c3/c4, table, btn, badge <status>, kv, tabs, actions, row, flash, empty). Do not add CSS files; inline `<style>` in a template is fine if small.
- Jinja globals: `money(c)`, `csrf()`, `current_user()`, `portal_contact()`, `firm()`, `today()`. Filters: `|money`, `|hours` (minutes -> "1.50"), `|d` (date), `|dt` (datetime), `|iso`.
- Helpers in `app.helpers`: `parse_money`, `parse_date`, `parse_minutes` ("1.5", "1:30", "90m"), `client_ip`, `cents_to_str`.
- Services: `app.services.mail.send_email(to, subject, html, text=None, attachments=[(name, bytes, mime)])` (logs to a dev outbox when SMTP unset; `dev_outbox()` returns recent), `app.services.sms.send_sms(to, body)`, `app.services.pdf` (DocPDF(firm, title), html_to_pdf_body, save_pdf, money).
- Call `audit(action, entity, entity_id, detail, user_id)` from `app.models` for create/send/sign/pay/void/delete actions.
- Numbering: `Firm.get().next_invoice_number` / `next_matter_number` with prefixes. Increment and commit atomically when you assign one.
- Dates in forms are `YYYY-MM-DD`. Store naive UTC datetimes.
- Keep it plain and fast. No JS frameworks. Small vanilla JS inline is fine.
- Copy style: plain English, no em-dashes anywhere (use commas or periods), no marketing tone.
